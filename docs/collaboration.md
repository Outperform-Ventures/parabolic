# Collaborative editing

Saved document bodies and issue, project, and initiative descriptions use shared Yjs documents instead of competing HTML replacements. The TipTap editor binds to the `default` XML fragment and uses the collaboration extension's undo manager. A same-origin WebSocket at `/collaboration/:kind/:id?field=:field` exchanges synchronization and awareness messages. The awareness state carries real cursor/selection positions; displayed user identity comes from the authenticated account on the server.

The permitted pairs are `documents.content`, `issues.description`, `projects.description`, `initiatives.description`, and `comments.body`. Other fields are rejected. The field parameter can be omitted, so the original `/collaboration/documents/:id` URL remains compatible. Comment rooms enforce the author/admin editing rule; the regular comment edit dialog retains its explicit Save/Cancel draft behavior. Unsaved issue and comment composers use local drafts until an entity exists.

Browser cookies authenticate the socket. API clients may authenticate the upgrade with a bearer token. Every room open and incoming update checks current account, workspace, document, and token permissions. Read-only credentials receive content without write access. Membership/privacy changes revalidate connected readers, and heartbeat checks detect expired sessions. Origins must match the service, its configured public URL, or an explicit allowed origin.

SQLite stores binary snapshots in `collaboration_rooms` and immediately appends received updates to `collaboration_room_updates`. The room key includes kind, entity ID, and field. Existing document snapshots and pending updates migrate atomically from the original document tables. A snapshot compacts each 128 updates and when a room closes. Empty rooms are released after thirty seconds. Browser updates also persist in IndexedDB under the current service origin, workspace, account, and entity/field. Offline edits merge during the next state-vector exchange. Content must first be available locally before it can be opened offline.

The server projects CRDT content to the entity's ordinary HTML field after 700 milliseconds without a new update, preserving REST/GraphQL/SDK consumers, search, events, and document version history. Explicit REST changes and version restores update the active CRDT fragment and reach all connected peers. The headless schema preserves headings, formatting, tables, checklists, image dimensions, code languages, mentions, date mentions, collapsible sections, inline custom emoji, and Mermaid source. Rendered Mermaid SVG is not used as stored content.

The implementation uses the open Yjs protocols and TipTap's [Collaboration extension](https://tiptap.dev/docs/editor/extensions/functionality/collaboration). It does not require a hosted collaboration service or hosted AI.

`tests/platform/collaboration.test.ts` verifies independent concurrent operations across all permitted entity types, authenticated presence, HTML/history projection, API replacement, restart persistence, legacy-state migration, rejected unauthenticated/read-only/revoked writes, comment authorship, and custom-node round trips. `tests/platform/collaboration.spec.ts` runs two actual browser accounts, holds their outbound socket messages while both edit, then verifies merged text and real remote carets. It also verifies API restore, reload, private-document access removal, and shared issue/project/initiative descriptions.

Titles, properties, and other entity fields retain the normal version-checked API behavior. WebSocket frame size is bounded to 512 KiB, awareness to 64 KiB, and idle connection checks run every fifteen seconds. These bounds and the existing service/database topology should be reviewed against the organization's content sizes and deployment load; the functional tests do not establish an unlimited concurrent-user capacity.

Opening an empty description does not project a formatting-only empty paragraph into the API. This prevents viewing an issue from creating history or waking a snoozed triage issue. Permanent deletion destroys active rooms without writing new snapshots during shutdown. Inline custom emoji use only authenticated workspace attachment paths and preserve shortcode text when copied as Markdown; deleting the emoji removes insertion choices while historical usages retain image access. Viewer name preferences change displayed peer/caret labels without changing authenticated awareness identities.
